# v0.3 双线验证

本轮将正式工具与 Super-agent 架构原型分别验收。v0.2 冻结实验、v0.2.0 可执行文件和 v0.2.1 文档发布保持不变；旧结果不能作为新程序的实测结果。

## 证据入口与口径

- 主工具：`scripts/run_v03_trial.py` 每次新建一个不可复用的试验编号，调用前冻结源代码和输入哈希，记录运行中状态；中断后保留原状态，不自动重试。
- 陌生小案例：温度转换器为单 Node 应用，不要求数据库、网关或 Compose。模型只接收 `benchmarks/temperature-converter` 两份设计文档；`scripts/check_temperature.py` 由操作者在生成之后独立执行，不进入模型上下文。检查数值边界、类型拒绝、同单位转换及 HTTP 输入错误。
- 原型：独立报告真实角色会话、隔离候选、集成结果、任务状态、中断恢复和用量，不将假模型测试写成真实生成。
- 索引：`scripts/evidence_v03.py` 只读扫描指定新证据目录，列出全部发现的报告，保留失败和无法读取项。索引不从模型文本推断独立验收通过。

## 发布门槛

`scripts/build_dual.ps1` 先运行回归，再将两个程序构建到不同子目录。只允许新建工作区 dist 下的目录，不能覆盖已发布文件。`scripts/package_v03.py` 检查密钥、逐文件计算哈希并回读 ZIP 校验；包内附两个程序各自的输入示例。

构建成功不等于发布验收通过。两个最终文件仍需分别在中文／空格路径和现有干净 Windows 检查启动、输入解析、真实调用、生成、取消及结果入口。缺少 Node／Docker 必须明确未验证。
