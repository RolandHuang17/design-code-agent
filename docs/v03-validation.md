# v0.3 双线验证

本轮将正式工具与 Super-agent 架构原型分别验收。v0.2 冻结实验、v0.2.0 可执行文件和 v0.2.1 文档发布保持不变；旧结果不能作为新程序的实测结果。

## 证据入口与口径

- 主工具：`scripts/run_v03_trial.py` 每次新建一个不可复用的试验编号，调用前冻结源代码和输入哈希，记录运行中状态；中断后保留原状态，不自动重试。
- 陌生小案例：温度转换器为单 Node 应用，不要求数据库、网关或 Compose。模型只接收 `benchmarks/temperature-converter` 两份设计文档；`scripts/check_temperature.py` 由操作者在生成之后独立执行，不进入模型上下文。检查数值边界、类型拒绝、同单位转换及 HTTP 输入错误。
- `scripts/check_temperature_project.py` 在临时端口启动已安装依赖的生成项目，清理环境中的模型密钥、执行独立 HTTP 检查并终止进程树；报告必须写在项目外，保留源文件前后哈希，不能复用旧报告路径。
- 原型：独立报告真实角色会话、隔离候选、集成结果、任务状态、中断恢复和用量，不将假模型测试写成真实生成。
- 索引：`scripts/evidence_v03.py` 只读扫描指定新证据目录，列出全部发现的报告，保留失败和无法读取项。索引不从模型文本推断独立验收通过。

## 发布门槛

`scripts/build_dual.ps1` 先运行回归，再将两个程序构建到不同子目录。只允许新建工作区 dist 下的目录，不能覆盖已发布文件。`scripts/package_v03.py` 检查密钥、逐文件计算哈希并回读 ZIP 校验；包内附两个程序各自的输入示例。

构建成功不等于发布验收通过。两个最终文件仍需分别在中文／空格路径和现有干净 Windows 检查启动、输入解析、真实调用、生成、取消及结果入口。缺少 Node／Docker 必须明确未验证。

无 Guest Additions 或来宾账户凭据时，使用 `scripts/build_dual_acceptance_iso.py` 创建新的只读验收介质，包含两个程序、示例、环境清单助手和哈希；不含 API 密钥。该脚本不覆盖历史 ISO，也不启动或修改虚拟机。界面验收与传回证据仍需单独完成。

`generic-02` 暴露“测试通过但 npm start 不监听”的缺口，因此加入固定 HTTP 就绪探测。就绪探测只证明服务真实监听，不能代替温度转换业务验收。借阅浏览器检查覆盖新增、借出、库存不足、归还、刷新后的状态；全部由外部浏览器操作完成，未人工修改生成源码。

Space 的续跑与最初全新生成分别记录。`space-03-wide-context` 的独立浏览器检查发现登录地址跳到网关而非身份提供者，返回404，后续答题、计分、暂停及管理网页检查因此跳过。配置审查还发现 game/question/user/admin 四个容器执行占位命令，业务集中在网关，违反原始文档第7、44行的微服务要求；HTTP通过不能覆盖这一缺陷。当前未据这些结果宣称原始复杂案例稳定自动完成，也未宣称千人并发或生产部署通过。

## 原型、打包与验收

原型五次宿主实跑（包含三次新任务、两次续跑）的逐项状态、67 个新增请求和费用见 [原型实跑](superagent-results.md)。健康服务的一次续跑通过三项自带测试、构建与六项独立 HTTP／重启检查；温度转换任务保留截断、审查阻塞、自带测试失败和 HTTP 崩溃证据。宿主恢复演示在同一 Python 进程重建协调器，不能描述为操作系统崩溃恢复。

最终两个文件及各自构建来源见 [构建清单](../experiments/v03/build-final.json)。工具回归为 **147 通过、1 跳过**，跳过原因为 Windows 符号链接权限。干净 Windows 的最终文件验收记录另存于 [clean-windows](../experiments/v03/clean-windows/)；缺少 Node／Docker 时，测试必须记录未验证。

最终主程序在干净系统中完成0813连接、两份输入解析、真实生成、取消与结果目录入口；同时验证中文／空格的只读介质路径和本地磁盘路径。最终主程序生成任务为 `run-20261106-171739-58af4633`（24轮响应、用量估算3.005118元），取消任务另存。缺少项目运行环境时实际状态为 `completed_with_gaps`。导出后在有Node的宿主上，六项自带测试、构建和六项独立HTTP／重启检查通过；这些结果不替代干净系统中的未验证。

原型另做了安全暂停、关闭exe、启动新进程、恢复SQLite、取消、未知请求确认和报告入口检查，见 [恢复比对](../experiments/v03/clean-windows/independent-recovery.json)。两个exe的SHA256均与来宾环境清单一致。证据通过只连接本机回环接收端的.NET助手导出，接收端随后关闭，虚拟机恢复禁止NAT访问宿主回环的设置。

费用按输入 12、输出 27 元／百万 tokens 的保守上界估算，缓存折扣不用于放宽预算，不代表平台最终账单。取消和结果未知的请求保留费用预留。各 trial 的原始 receipt 不因外部复验而被重写；独立结果保存在相邻 JSON。

历史 v0.2 的九次冻结实验、旧 Release、人工修正说明均保留。当天小样本与控制器迭代不能用于推导一般成功率。
