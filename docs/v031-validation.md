# v0.3.1 桌面收尾验证

本轮更新两个桌面程序的界面与任务生命周期。v0.3.0 原始成果、失败谱系和已发布文件保持原样；旧 Space 的44项自带测试、27项HTTP和18项浏览器结果仍属于原来的全新生成加三次反馈续跑，不作为本轮重新生成的成绩。

## 界面与稳定性

两个程序统一为浅色工作台，项目与模型设置分开，执行、取消及结果入口固定可见。主工具展示真实阶段、设计提示和验证结果；原型分别展示工作项、会话、检查、资源及日志，工作项完成只表示候选已合入。

2026-11-06最终界面审阅时阅读了Anthropic的[frontend-design skill](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)，用于检查信息层次、控件可读性和错误状态表达。该阅读属于收尾审阅，不追溯为历史实现过程；未复制其代码，也未引入新运行时。

修复了误选恢复目录产生文件、空输出被解释为当前目录、结果入口指向旧任务、资源分页重播首页及恢复后残留旧状态等问题。运行中配置锁定；关闭先取消并等待工作线程保存记录，再释放界面和数据库。清空可见密钥后不再隐式使用旧环境值，显式读取环境变量会刷新Windows用户配置。

任务存储格式和主工具模型协议未迁移。原型新建使用唯一子目录，恢复入口在临时数据库副本中预检，未知请求仍需确认，历史记录与费用预留保留。

## 回归与构建

最终候选04构建时，本机回归为 **200通过、1跳过，25.39秒**；跳过项是Windows符号链接权限。两个exe对应源码提交 `fc3059f`，构建来源、精确源码与SHA256见[构建清单](../experiments/v031/build-final.json)。它是本机验证，不是GitHub Actions通过记录。

新增原生Tk回归最初在单独执行时通过，混合全套运行却发生Tcl对象在线程中延迟回收的崩溃；随后将各原生场景隔离到独立进程，并分别验证产品关闭竞态。失败及后续验证保存在[回归历史](../experiments/v031/regression-history.json)。没有将测试进程崩溃直接表述为已确认的成品exe崩溃。

[布局压力记录](../experiments/v031/independent-layout.json)覆盖两个程序、两种窗口尺寸与三种Tk字体缩放，共12个场景。模拟只修改测试解释器，不改变操作系统DPI。关键按钮均可见，长路径及任务表可滚动；极长单元格仍可能需要手动拉宽。

## Windows 来宾实测

最终候选04已在本轮Windows来宾完成原始架构文档[解析预览](../experiments/v031/clean-windows/main04-preview.png)和[0813真实连接](../experiments/v031/clean-windows/main04-connection.png)。预览实际显示两份文档、13个图和1条确定性提示；连接成功不代表生成项目已通过验证。

在同一来宾、微软拼音组合下，向密钥框输入公开的17字符占位串，实际显示遮蔽字符，未观察到中文候选窗；移出密钥框后，在普通URL字段输入 `nihao`，实际出现中文候选。对应[密钥框观察](../experiments/v031/clean-windows/main04-ime-dummy.png)和[普通字段恢复](../experiments/v031/clean-windows/main04-ime-restored.png)。这只验证该机器与输入法组合，不能推断所有输入法、Windows版本或硬件环境的行为。

两个最终exe均从中文、空格路径运行。来宾未安装Python、Node或Docker；[环境清单](../experiments/v031/clean-windows/environment-final.txt)同时记录介质中的最终exe哈希。真实API验收采用进程内环境变量注入密钥，未使用共享剪贴板或密钥文件；该私有验收助手不属于发布程序或运行依赖。

健康服务输入是操作者编写的小型演示，不是老师原始Space材料或冻结性能基准。本轮不新增复杂Space生成实验，不能据此推导陌生项目普遍成功率。来宾缺少Node的原始“未验证”结果保留，宿主复验在私人副本中执行，不回写原报告；独立HTTP检查前后源码哈希相同。

原型自带测试失败为 `ERR_SERVER_NOT_RUNNING`：测试同时使用 `t.after` 与显式 `close`，重复关闭服务器。只读审查者已将它列作advisory却仍批准；这表明审查意见不能代替实际执行。原始生成源码未人工修补，也未将6项HTTP通过写成全部质量检查通过。原型仍定位为调度、独立会话、资源读取与恢复机制演示。

原型界面分别观察了工作项、检查结果、资源读取末页禁用“下一页”和打开实际结果目录；主工具解析、连接、生成与取消截图及全部原始记录见[本轮证据](../experiments/v031/README.md)。恢复前一次手工输入的错误目录被拒绝，随后通过目录选择器选择实际任务恢复；该操作失败也保留截图。

四个任务共43个有效响应，费用上界估算合计 **3.318882元**，按输入12元、输出27元／百万tokens计算，不扣除缓存优惠。连接探针、结果未知请求及历史累计账本另列，不能当作最终账单；详见[运行汇总](../experiments/v031/clean-windows/independent-runtime-summary.json)。
