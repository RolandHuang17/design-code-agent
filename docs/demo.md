## 三分钟演示

1. 打开 exe，说明模型平台与考核要求的区别。不要展示明文密钥；连接测试展示平台和模型响应。
2. 加载两份原始材料，点击免费解析预览，指出 13 个图代码块与可用性指标冲突。
3. 展示一次真实 run 的 plan、生成文件和事件日志，解释工具调用如何实际写文件。
4. 展示 checks-0 和后续检查，定位一次具体失败和对应修复快照；若本次没有发生修复，明确说明，用离线回归测试讲解该机制。
5. 打开生成项目并完成答题与查看成绩，再展示权限和持久化的独立测试结果。未完成真实验收前不要将这一步录成成功演示。
6. 展示 traceability 与最终报告，主动说明已验证范围和基础设施未验证项。

外部 HTTP 验收：在服务启动并取得三个不同权限 / 身份的游戏 OIDC access token 后，配置 `SPACE_USER_TOKEN`、`SPACE_ADMIN_TOKEN`、`SPACE_OTHER_USER_TOKEN`，运行 `python scripts/evaluate_project.py --base-url http://127.0.0.1:3000`。脚本位于生成目录外，验证权限、暂停、非法分数、计分及重复提交；会创建并清理一条测试题目。重启后的持久化及浏览器体验需另外验证。

## 应能讲清楚的问题

**为什么这是 Agent，而不只是把文档发给模型？** 模型能够请求多个真实工具、观察结果、修改已有文件；宿主把测试失败反馈回模型继续修复，有状态且有闭环。

**是不是多 Agent？** 当前是单一控制器的多阶段实现，分别承载理解、规划、生成与验证职责。未来可以拆成多个 Agent，并用同输入同预算对比，不能把阶段名称当作多 Agent 实现。

**怎么防止它宣布成功却没有通过测试？** 最终状态由宿主检查结果计算。模型文字不能改变检查状态。未运行项目检查时保持 completed_with_gaps。

**如何证明设计与代码对应？** 保留原始输入和哈希，生成包含来源行号、代码和测试路径的追溯表。自动校验可验证链接，真正语义一致性还需独立审查。

**为什么还会生成错误？** 输入有缺失和矛盾，模型可能错误理解接口、依赖或跨服务关系。工具循环让错误可观察、可修复，但不保证任意输入都能成功。

**预算如何控制？** 每次请求前预留，响应 usage 结算。未知网络结果保留预留；50 元是多个任务共享的累计上限。价格需要事先核对，缓存折扣不放宽预算。

**如何保护本机？** 文件工具限制工作区；命令种类固定、子进程环境精简。执行生成代码不是沙箱，当前版本仍需在合适的开发环境运行。

**使用 AI 辅助了吗？** 如实说明使用 AI 辅助实现，并能够指出自己已经理解和复核的部分。不要背诵不理解的源码结论或将手动修复说成 Agent 自主结果。

- 在另一台无 Python 的 Windows 上验证 exe；记录系统版本和实际完成的操作。
- 选一份可复现的真实生成案例，报告注明平台、模型、费用、失败与人工修正。
