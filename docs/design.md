# 实现结构与工程取舍

这是一个由宿主约束执行的单控制器 Code Agent。规划、生成和修复属于阶段角色，不将其包装为已实现的多 Agent 协作。

## 模块

| 模块 | 输入与输出 | 关键责任 |
| --- | --- | --- |
| inputs | 两份 Markdown → 结构化对象 | 原文、SHA256、章节、代码块、来源行号、确定性冲突提示 |
| provider | messages / tools → assistant | 平台适配、非思考模式、工具调用、错误处理、费用结算 |
| budget | 预留 / usage → 累计费用 | 跨进程锁、原子账本替换、不确定请求保守计费 |
| engine | 文档 / provider → run 目录 | 阶段调度、上下文重建、独立验证、最多三轮修复、报告 |
| tools / safety | 工具参数 → 文件或结果 | 参数与路径校验、读后修改、唯一替换、版本快照、脱敏 |
| checks | 检查名称 → 状态与输出 | 固定命令、精简环境、超时、取消、子进程树清理 |
| gui / cli | 用户操作 → Agent 调用 | 配置、后台线程、事件队列、日志与结果展示 |

## 输入中的问题

原文提到自然语言需求文档，但本次只提供架构文档和视图。工具不会凭空声称已获得完整需求。文档只定义 `GET /play` 和简单 RPC，题目判定、答案、权限、暂停等需要补充，生成计划必须记录这些假设。

架构可用性为 99.99%，错误预算却写 1%；同一统计窗口下两者不一致。解析器显式给出该冲突，其余语义冲突由模型分析并写入决策记录。PlantUML 共 13 个代码块，对应 11 类图，不需要 Java 或 PlantUML 渲染即可提取。

## 生成目标

提示词要求保持微服务和 PostgreSQL，同时尽量实现 Redis、RabbitMQ、Elasticsearch、OAuth2 / OIDC 和指标等能力。Kubernetes、Terraform / AWS、Jenkins、Vault、Istio 需要配置及边界说明。**提示词中的要求不等于生成结果已实现**，必须看本次代码和验证记录。

原文推荐 Node 18；生成目标采用 Node 22+，属于显式技术版本调整。实际部署、云账号、域名、证书和集群不由工具自动创建。单机成功不证明千人并发和可用性目标成立。

## 执行与失败策略

阶段结束依据模型不再请求工具；随后宿主验证文件、JSON/YAML、JS 语法和追溯链接。缺失运行环境与执行授权会返回 unverified。检查失败触发修复，最多三轮。模型提前结束、API 出错、预算不足或轮次耗尽均写入报告。

上下文达到大小阈值后，不保留半截工具调用：使用原始输入、计划、现有文件目录、最近检查重新构建上下文。原始完整事件保留在磁盘。局限是文件数量较多时会产生额外读取，当前没有向量索引或自动中断恢复。

固定检查入口只限制模型直接选择的命令，不提供操作系统隔离。用户主动勾选执行后，npm 测试及构建脚本仍能访问当前账户权限内的资源。精简进程环境可避免直接继承 API 密钥，但不是强隔离承诺。

## 如何扩展

新增语言先增加固定验证配置和对应生成约束；新增工具要同时补 JSON schema、宿主参数验证和边界测试。多智能体协作可在后续研究加入，但应与此单控制器版本做相同预算、相同输入的对照实验。
