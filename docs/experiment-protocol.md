# 仓库级生成实验与评价口径

本文保留 v0.2 冻结实验口径（最多三轮修复）。v0.3 支持配置零至十轮，具体运行的实际配置、谱系及结果另见 [v0.3 验证](v03-validation.md)，两轮实验不合并统计。

## 实验输入和过程

使用老师提供的两份 Markdown 原文，以输入 SHA256 标识版本。记录模型平台、模型 ID、实际调用参数、工具版本、时间、API usage 和计价上界。百炼与 DeepSeek 官方实验分别报告，不混合为同一供应商结果。

一次实验由规划、生成、独立宿主检查和最多三轮修复组成。保存每次工具写入快照与原始检查输出。失败或人工中断也是实验记录的一部分；对网络不确定请求保留预算预留。

## 评价维度

| 维度 | 可观察证据 | 不应推导的结论 |
| --- | --- | --- |
| 可构建性 | 依赖安装、真实构建 / 语法检查退出码、Compose 配置检查 | echo 成功不能作为构建成功 |
| 功能正确性 | 生成项目测试，以及目录外独立 HTTP 验收结果 | 自动测试通过不代表所有需求正确 |
| 架构一致性 | 需求 / 图 → 服务 / 接口 / 数据 / 测试对应关系；实际服务通信 | 配置文件存在不证明服务实际工作 |
| 持久化 | 完成答题后重启服务，再读取原游戏和分数 | 同一进程内 GET 成功不证明重启持久化 |
| 权限 | 无 token、普通用户访问管理端、其他用户访问游戏的负面测试 | 单次拒绝不证明全面安全 |
| 可维护性 | 模块职责、错误处理、依赖耦合、接口文档与测试可读性的人工检查 | 文件多或注释多不自动代表可维护 |
| 开发效率 | 生成耗时、API 用量、修复次数和人工介入记录 | 单案例不能证明普遍效率提升 |

每项分别标注已运行验证、静态检查、未验证或失败。功能测试报告给出实际通过 / 失败 / 跳过数，跳过不计通过。架构覆盖可列 implemented / partial / unimplemented 条目数，但这些是逐项审查状态，不当作客观语义准确率。

## 独立性与人工介入

模型自己的测试可能遗漏同源错误，因此保留目录外的 HTTP 验收脚本。验收约定在生成前给出，脚本不会由模型改写。该验收仍只覆盖明确场景，不能替代完整软件评测。

人工修改应在原始输出副本上完成，列明文件、原因、前后差异和复检结果。若再次调用 Agent 修复，另存新的会话和预算记录，标记为额外修复，不回写原始成功率。

v0.1 只以一个案例进行可行性验证；v0.2 增加借阅案例与0/3轮修复的小样本对照，固定设置与当前状态见 [v0.2 协议](v02-experiments.md)。不进行未经实验支持的统计显著性、准确率提升或多 Agent 优于单 Agent 的宣传。
